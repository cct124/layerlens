# M0-00a 提交格式检查

## 目标与验收

在首次脚手架提交前建立格式门槛，让提交检查对应 Git 索引中的实际内容，保留部分暂存与未暂存修改。检查完成后，按用户授权提交整个工作区并推送到 `origin/dev`。

- Husky 管理 `pre-commit`，通过 npm `prepare` 安装；独立 `format:staged` 命令可复现提交检查。
- Node 检查器读取索引 blob，通过 Prettier API 或 rustfmt 标准输入检查，不自动格式化、stash 或 `git add`，不修改索引或工作区。
- 普通提交只检查暂存的 A／M／R／C 文件，删除项跳过，支持中文和空格路径；暂存格式配置变更时检查整个索引。
- `npm run format` 统一 Rust 与仓库内 Prettier 支持的文件，提供 Rust、Prettier 各自的格式化与只读检查入口；`.rustfmt.toml` 固定 edition 和 style edition 为 2024。
- `test:hooks` 覆盖索引与工作区内容不同、格式失败及配置变更等行为，验证检查前后暂存与未暂存内容保持不变，并纳入统一检查。
- 本地 hooks 与 CI 完整检查共用格式规则；远端分支保护根据实际权限核验，不以本地配置替代远端强制规则。
