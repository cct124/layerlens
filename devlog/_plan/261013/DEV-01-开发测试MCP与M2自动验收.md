# DEV-01 开发测试 MCP 与 M2 自动验收

## 目标与验收

按[开发测试 MCP](../../../docs/08-开发测试MCP.md)建立测试实例内的业务、界面和观测入口，减少跨层回归对桌面坐标操作的依赖，并为 M3／M4 提供可复用的测试基础设施。设计规则以该文档为单一维护来源。

- 第一批通过真实 MCP 客户端连接同一桌面实例，执行打开／切换／关闭、选区、固定任务、读取和清理闭环，保持既有生命周期、预算与错误语义。
- 第二批验证真实 WebView 驱动，提供实际交互和前端同步观测；业务调用、DOM 合成事件、真实输入及原生系统验收分别记录。
- 第三批以确定性脚本复现稳定场景，形成运行报告并接入 Windows CI；普通发行构建无开发入口，测试实例及等待／订阅／后台资源可完整退出。
- M2 证据回填现有任务，未执行的原生窗口与 DPI 项继续保留。开发测试通道完成不代替产品 MCP 或真实 H5 模块验收。

## 实施顺序

### 第一批：业务测试闭环

1. 从 `src-tauri/src/lib.rs`、`commands.rs`、`workspace/runtime.rs`、`workspace/operations.rs` 与核心契约定位入口及引用，明确需要复用的边界校验和预算；不绕过桌面准入另建核心。
2. 验证并锁定候选 MCP SDK，落地编译特性、显式启用、回环连接、实例身份和受控样本／输出目录。先做初始化、工具枚举及结构化结果的真实客户端互通。
3. 接入文档、图层、选择、任务与清理能力，增加核心状态查询和有界等待。完成设计文档中的最小闭环，补齐过期、幂等、乱序、隔离与退出的必要负向场景。
4. 验证未启用特性／运行开关时开发入口不存在，开发实例隔离有效；执行受影响格式、类型、lint、测试及构建检查，记录真实命令与结果。

### 第二批：界面驱动与同步观测

1. 用最小原型核验 Windows WebView 驱动与当前 Tauri 版本的输入、截图和退出路径，再确定内嵌或独立驱动形式。
2. 在实际状态应用路径观测核心序号和前端代次，通过真实交互覆盖菜单、任务面板、清理弹窗与区域草稿／取消。必要测试桥保持类型化和有界，不暴露任意执行入口。
3. 对照 [M2-02](../260920/M2-02-桌面选区与任务交互.md)及 [M2-03](../260923/M2-03-主动资源清理与任务失效.md)回填证据；保留系统文件选择器、跨屏 DPI、贴靠等原生专项未测项。

### 第三批：确定性回归与 CI

1. 稳定流程固化为无需模型判断的脚本，预期来自样本和验收规范；报告包含操作、版本、关联 ID、实际状态与失败阶段。
2. 验证重复执行、测试实例隔离和正常退出；Windows CI 使用同一真实入口，分别验证普通构建与开发测试构建。
3. 汇总 M2 验收缺口与效率测量结果，达到本任务出口后归档，再推进固定快照参考图及受控导出；不为尚未实现的能力注册占位工具。
