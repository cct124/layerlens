# M1-01 文档生命周期与后台任务

## 目标与验收

把 M0 的同步 PSD 原型接入 Rust 应用核心，先建立多文档和后台任务的权威状态，再接入最小桌面打开／切换／关闭与预览流程。遵循[技术架构](../../../docs/02-技术架构.md)、[产品与交互](../../../docs/01-产品与交互.md)及[首版解析范围](../../../docs/07-PSD首版支持与解析器决策.md)。

- 文档与作业使用专用 ID 和明确状态，核心管理活动标签、稳定修订及资源所有权；前端不持有另一份权威文档状态。
- 打开、切换、关闭和失败恢复可以独立测试；新文件失败不损坏已有文档，完成顺序不使旧请求覆盖当前状态。
- 耗时读取、解析和解码在有界后台运行，锁只覆盖短时状态访问；明确并发、排队、文档数量与缓存字节上限和拒绝行为。
- 取消、关闭及退出能阻止过期结果发布并释放任务持有资源；如底层同步解析不能中途停止，必须明确实际完成后才释放其执行名额和内存，不把 UI 已取消当作计算已终止。
- 预览按文档修订与实际渲染参数复用，关闭／失败／取消路径维护预算与所有权；命中、淘汰和重复请求可复现验证。
- 桌面薄接口复用核心规则，DTO 生成与契约检查同步；验证多标签、失败提示、关闭后释放和可见响应，不将 CLI 耗时当作 UI 验收。

## 已完成

### 核心生命周期批次

- [核心文档服务](../../../crates/layerlens-core/src/documents/mod.rs)新增打开／复用、显式重载、激活、关闭、固定修订引用和退出入口。文档、修订和打开作业使用不同 ID；打开成功才新增标签，重载保留文档 ID，失败保留已有内容。只有最新打开意图允许自动激活，手动切换优先；关闭活动文档优先选择右邻，其次左邻。
- [后台执行与发布](../../../crates/layerlens-core/src/documents/worker.rs)采用单个标准线程，文件系统规范化及同步解析不占用状态锁。已知路径立即复用，未解析的路径别名可能暂占不同作业槽位，后台规范化后复用同一文档；同名不同目录不合并，硬链接不承诺合并。关闭记录早期作业范围，阻止尚未规范化的别名请求重新打开已关闭文档。
- 排队取消立即完成，运行中取消保留执行名额及预留额度，直到同步解析返回且未发布数据销毁。发布决定在状态锁内裁决，`Finishing` 阶段在锁外销毁旧／未发布修订，结束后才归还作业名额并通知完成。新重载只有准入成功后才替代旧请求；第三方加载 panic 转为可识别失败并归还额度。
- [修订与作业模型](../../../crates/layerlens-core/src/documents/model.rs)通过只读 `DocumentLease` 固定 PSD 事实、单位、来源和指纹；源文件替换／删除、重载、关闭及服务退出不改写既有引用。作业结果只保留 ID、错误和核心排队／执行计时，不持有解析文档，不累积无界终态历史。当前不暴露绕过调度的解码入口，不生成 CSS。
- [源修订资源账本](../../../crates/layerlens-core/src/documents/budget.rs)先按单文件上限预留，再按实际源字节／累计声明像素结算；解析对象销毁后才由 RAII 归还额度。旧修订、关闭后仍被持有的修订和在途解析都计费。这是保守准入计量，不是 heap／RSS 硬上限；预览、PNG 与缓存由下一小节的独立账本管理。
- `request_shutdown` 停止准入并请求取消；预览批次还增加锁外缓存／排队预览引用清理。`shutdown`／析构在状态锁外等待工作线程结束并释放注册表，外部修订及 PNG 引用仍有效。等待、退出及可能销毁大修订或图像的操作须由适配层放入后台；当前未提供异步事件通知。

默认配置为 1 个解析线程、4 个未完成作业、8 个存活／预留修订、256 MiB 源字节和 64 Mi 声明像素。M0 单文件默认限制保持 64 MiB 源文件、16 Mi 累计声明像素、4096 条图层记录和 128 MiB 解码缓冲预算。全局配置必须至少容纳一次完整解析预留；重载要容纳新旧修订共存，保守预留可能拒绝实际较小的输入。

该批新增[生命周期烟测示例](../../../crates/layerlens-core/examples/document_lifecycle.rs)、[16 项确定性核心测试](../../../crates/layerlens-core/src/documents/tests.rs)和 3 项真实文件集成测试。

### 预览调度、缓存与资源预算批次

- [预览服务](../../../crates/layerlens-core/src/documents/preview/mod.rs)提供 `preview`／`cancel_preview`，打开与预览共用单线程、FIFO 顺序和 4 个未完成作业上限。仅支持原尺寸保存时合成 PNG，保留适配器的能力和限制，不实现缩放、区域渲染或图层重新合成。相同修订在途请求返回同一作业；取消其中一个句柄会取消共同工作，丢弃句柄不自动取消。
- 缓存 key 为文档 ID、修订 ID 和 `SavedCompositePng` 种类，采用 LRU 条目／容量限制；命中不解码也不占用作业槽位。成功重载、关闭及退出取消过期工作并使缓存失效，失败重载保留旧预览。缓存和源修订析构在状态锁外执行，排队取消清理期间仍保留作业名额；运行中的同步计算结束后才能释放额度。
- [独立预览账本](../../../crates/layerlens-core/src/documents/preview/budget.rs)默认 128 MiB 解码预留、64 MiB 单张 PNG、128 MiB 存活输出总量、64 MiB／16 项缓存。执行前预留完整的单文件解码额度和单张 PNG 上限，编码后按 PNG 分配容量结算；输出准入不足时逐项淘汰最旧缓存，外部仍持有图像则继续计费，不足明确失败。缓存上限任一为零可禁用缓存。这组保守默认值覆盖本批样本输出，不代表经过全场景调优，也不是 RSS 硬上限。
- [预览引用与结果](../../../crates/layerlens-core/src/documents/preview/model.rs)将 PNG 与源修订分开：`PreviewLease` 可在关闭、重载和退出后继续读取图像，却不保留整个 PSD。共享引用不重复计费；完成句柄、完成结果及其状态副本也可能延长 PNG 寿命，最后一个引用释放才归还输出额度。快照提供解码预留、输出／缓存容量、命中、合并和淘汰计数。
- [有界 PNG 编码](../../../crates/layerlens-core/src/psd/png_output.rs)通过现有 `png` 依赖流式写入，在追加和扩容前检查限额，拒绝发布超限或不完整图像。保留同步适配器原有编码入口，因此 M0 `bench:psd` 对照路径未改成缓存测量。
- 新增[预览烟测示例](../../../crates/layerlens-core/examples/document_preview.rs)、[16 项预览单元测试](../../../crates/layerlens-core/src/documents/preview/tests.rs)，并把[文档服务集成测试](../../../crates/layerlens-core/tests/document_service.rs)从 3 项扩至 6 项。两批均同步 README、技术架构及本记录；无新增依赖、锁文件、第三方解析器或前端接口变化。

## 开发顺序

1. **核心生命周期**：先检索 `PsdDocument`、`ParseLimits`、`source.rs`、当前 DTO 及 Tauri Commands 的定义与调用；确定文档／作业 ID、打开请求与稳定修订关系，新增职责独立的注册表及状态转换。首批通过纯核心测试验证打开成功／失败、活动文档切换和关闭。
2. **有界后台与取消**：以单个重操作并发作为起点，明确有限排队和满载拒绝；计算与发布分开，检查关闭／取消／替代请求的提交顺序。同步解析的取消粒度按真实实现记录；如必须硬中止，再单独评估隔离进程及成本。测试使用可控执行器或检查点，不依赖固定休眠。
3. **多文档预算与预览缓存**：沿用单文档预检和解码限制，增加跨文档／任务／缓存的所有权与计量；确认缓存数据形态和 key 后才确定字节上限。先测一次请求与重复命中，再验证淘汰、关闭及引用被任务持有时的释放，避免缓存和解码路径重复计算业务规则。
4. **最小桌面接入**：暴露打开、列出、切换、关闭、状态通知和按需预览接口，前端只保留视图状态。完成顶部标签、错误恢复和预览可见验证；完整图层树、只读属性及选区界面后续按 M1 目标细分。

每步完成后保留独立可评审的实现和记录；不顺手扩大 PSD 支持模式、引入 CSS 转换或实现复杂素材渲染。
