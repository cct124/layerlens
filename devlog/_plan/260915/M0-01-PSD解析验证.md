# M0-01 PSD 解析验证

## 目标与验收

在已完成的最小工程上验证 Rust PSD 候选解析器，形成可复现的样本能力矩阵与首版支持子集。具体数据语义以[PSD 数据与素材](../../../docs/03-PSD数据与素材.md)为准，样本和阶段出口以[实施与验收](../../../docs/06-实施与验收.md)为准。

- 用有来源说明和预期结果的真实、合成 PSD 样本核对文档、图层层级、文字与分段样式、坐标、合成预览及简单位图导出。
- 将第三方解析类型隔离在适配器内部，验证结果不改变 PSD 只读边界，也不将缺失值伪装为完整数据。
- 记录逐样本的能力、差异、限制及失败原因，依据证据决定首版支持子集和解析器版本。
- 记录环境、样本指纹、冷／热条件、耗时和峰值内存；验证稳定源数据、外部文件变化、损坏输入及资源上限处理。

| 合成样本可复现性                              | `npm run fixtures:check` 逐字节核对 PSD、预期清单与指纹，不写文件                                                      |
| 独立核心测试                                  | 29 项通过（16 项单元测试、13 项集成测试），覆盖精确 RGBA、负坐标、缺失预览、全部截断前缀、预算、稳定源及审查补充的边界 |

### 候选与依赖评估

- 上游：[Vasyanator/ag-psd-rs](https://github.com/Vasyanator/ag-psd-rs)，实际 package `ag-psd`。已核验官方索引和发行归档 `0.3.0`（2026-09-06，未撤回），SHA-256 `6470c6a2f96a00a8d4154504020b34807c2282438c98f90f5069ef3f8cb0e7bf`，对应提交 `ff8754fb5dfb3b91f4e28dd37df98f6404f1dbcc`；锁文件保存发行校验值。
- MIT，与本项目许可兼容；Rust 1.85／edition 2024，运行依赖仅 `flate2`，无桌面或平台 SDK 依赖。维护历史较短（仓库创建于 2026-06-28，最近推送 2026-09-06），需要自有样本验证。上游样本不全部随代码 MIT 授权，因此本轮没有复制其设计稿。
- PNG 编码复用锁文件已有 `png 0.17.16`，指纹复用 `sha2 0.10.9`，均为 MIT OR Apache-2.0；无新增前端依赖，Cargo 仅新增候选包及核心依赖关系。只在 Windows x64 验证，不据纯 Rust 实现宣称跨平台兼容。
- 候选 `use_raw_data` 持有压缩通道副本，可在源字节和文件句柄释放后解码；不是零拷贝。懒解码不继承读取预算或严格模式，故在调用前核验 RAW 长度、RLE 行表及实际展开数量。
- 候选部分元数据按声明长度分配，位图预算不能约束这些分配；本轮只允许有界的已审查结构，未验证的附加块先拒绝。放宽准入前必须加入对应长度／语义验证，不能仅修改白名单。
- 源码核验发现文本路径会规范化换行并裁去末尾换行／调整样式长度；这可能与本项目保留原文的契约冲突。下一轮须以带 CR、LF、空白、emoji 和分段样式的样本验证，依据差异决定修补候选或替换，尚未决定生产选型。

### 真实稿专项测试：tab-1（2026-09-16）

用户提供并授权本地测试 `.local/psd-samples/tab-1.psd`，未授权公开设计内容。源文件 451,165,691 字节（430.27 MiB），SHA-256 为 `123d1debd26c0662211265b31b167f361072fe7af03c313f18e7edccae3d01bd`；测试后复核指纹一致，源稿未修改。样本、预览、通道 PNG、诊断代码与报告均被 `.local/` 忽略规则覆盖，不提交设计图或原文。

- 文档：PSD v1，5047×3517，RGB/8 位，72 DPI，4 通道，存在合成透明度。画布 17,750,299 像素，超过原型默认 16 Mi 像素；文件大小也超过 64 MiB。
- 结构：514 条记录中有 95 个组边界，规范化后 419 个节点（95 组＋324 内容层），最大组深度 4。95 文字、185 智能对象、28 形状、106 效果记录；这些特征可以重叠，不是相加互斥分类。
- 资源：33 个图像资源，包含 ICC；全局 `lnk2` 315,644,372 字节，占主要体积。按区段跳读可避免为结构盘点分配整个嵌入对象。全部图层矩形累计 55,948,148 像素，后续应区分源大小、嵌入对象、按需解码及缓存预算。

| 路径                                           | 实际结果                                                                | 结论                                                                  |
| ---------------------------------------------- | ----------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 原 `inspect_psd` 默认入口                      | `ResourceLimit`，未创建输出目录                                         | 正式核心尚不能打开该稿                                                |
| 专项探针仅提高到 512 MiB／256 Mi 像素          | `Unsupported`：仅允许 ResolutionInfo 资源                               | 单纯调大阈值不足以兼容                                                |
| 候选 strict＋handler 报错                      | offset 46，`Unread section data`；对应首个资源 1028                     | 未消费的未知图像资源使严格解析中断                                    |
| 候选允许 section 剩余字节，但保留 handler 报错 | offset 906978，gradient vector content not yet supported                | 存在实际未移植的渐变能力，不是纯预算问题                              |
| 候选探索模式，跳过位图                         | 419 节点、95 文字、204 个显式字符样式段、95 个变换                      | 与独立结构数量吻合，但容错可能忽略其他字段，未验原文／样式保真        |
| 候选 eager 保存时合成图                        | 5047×3517 RGBA PNG 生成，未自行重绘图层                                 | 避开 lazy helper 丢失 global alpha 的已知问题；不等于复杂图层渲染通过 |
| 原始通道抽样                                   | 5 个简单可见图层的通道 PNG 解码成功，完整保留包括画布外部分的矩形       | 探索模式输出，不作为生产独立素材与效果验收                            |
| 独立 PackBits 对照                             | 14,068 行严格解码；全部 alpha 相同，9,670,654 个不透明像素的 RGB 零差异 | 验证保存时合成像素；4,739 个半透明像素的去白底语义及 ICC 仍待验证     |

专项代码直接依赖已锁定候选，完全位于 `.local/psd-tab-1/probe/`，用于区别正式核心限制与候选能力。探索模式关闭 `strict` 与 `throw_for_missing_features` 仅用于发现可读取内容，不能视为生产修复。正式源码、默认预算及拒绝行为均保持本轮测试前状态。统计仅输出数量、偏移、指纹及限制，不记录设计文字和图层名称。

运行环境为 Windows 11 x64（10.0.26200）、AMD Ryzen 9 7945HX、物理内存约 31.69 GiB，debug 构建。元数据探索解析约 112 ms，进程峰值约 440 MiB；合成预览读取＋解析／解码约 2.63 s，PNG 编码约 2.23 s，包含诊断统计的探针总计约 6.10 s、峰值约 547 MiB；5 项原始通道抽样总计约 2.24 s、峰值约 564 MiB。峰值取 Windows 进程 `PeakWorkingSet64` 的 25 ms 轮询观察值，独立进程设 45 s／900 MiB 终止阈值，均未触发。原文件已被先前测试读取，未清空或控制系统缓存，以上是单次探索记录，不是冷启动、release 或 UI 性能承诺。

独立 Python/Pillow 验证器按行解码原文件合成 RLE，耗时约 1.42 s、峰值约 184 MiB。所有 alpha 和不透明 RGB 与候选 PNG 完全一致；半透明位置每个 RGB 通道有 4,736 个原始值差异，候选执行了白色底色去除，仍需 Photoshop 参考确认。缩略图已人工检查可展示完整多画板内容；未有独立 Photoshop 导出参考，不能宣称视觉完全一致。

本地复现入口：先在仓库根目录将 `CARGO_TARGET_DIR` 设为根 `target/`，执行 `cargo build --offline --locked --manifest-path .local/psd-tab-1/probe/Cargo.toml`；随后运行 `.local/psd-tab-1/run-probe.ps1 -Mode <core-expanded|strict|tolerant|explore|preview|layers>`。探针报告和 PNG 使用新建文件语义，重新实验需选择新的报告目录；不会覆盖本次结果。结构／独立像素对照入口为同目录 `inventory.py`、`validate_composite.py`，参数见脚本入口。

产物目录 `.local/psd-tab-1/`：`inventory.json`、逐模式 JSON、`preview.png`、`preview-thumbnail.png`、5 个 `layer-sample-*.png`、`composite-validation.json`。本次只新增忽略目录下的实验和更新开发记录，沿用此前未提交实现；未重跑不受影响的全仓测试或桌面构建。
