# 渲染器对比实验

## 目标与决策边界

在隔离开发实例中比较 LeaferJS、Konva、CanvasKit 对同一 PSD 的绘制效果、交互、资源生命周期及实现成本，为工作区选型提供证据。实验开始时三者均为候选，当前决定见下节；实验成功不代表替换正式预览，也不扩大[首版解析支持](07-PSD首版支持与解析器决策.md)。

2026-10-16 用户暂停渲染器定案及正式接入文档，转入 [RENDER-02 真实大稿对比](../devlog/_fin/261016/RENDER-02-tab-1真实大稿对比.md)，该轮已按约定在固定矩阵后结束。下文第三轮的 Leafer 主候选是当时的条件性倾向，不能作为后续预设结论；完整视觉与资源验收未通过，正式工作区仍未迁移。

## 当前选型决定（2026-10-17）

用户确认使用 **Konva 作为正式工作区的 Canvas 渲染框架**。该决定取代此前的 Leafer 主候选与暂不定案状态；RENDER-01／02 归档保留当时的实验结果与结论，不改写失败记录。正式接入尚未实施，当前工作区仍使用原稿合成图预览。

决策优先考虑长期维护、框架集成与问题排查成本，并结合已有样本证明的有限绘制／交互能力。不是将未通过的完整 PSD 视觉或资源验收改判为通过，也不声称 Konva 在所有性能指标上优于 Leafer。

2026-10-17 核对的官方依据：

- [Konva 变更记录](https://github.com/konvajs/konva/blob/master/CHANGELOG.md)保留自 2015-01-28 品牌迁移发布以来的演进历史；[官方仓库](https://github.com/konvajs/konva)提供跨框架入口、示例和测试说明，并说明维护者的商业编辑器产品 Polotno 为持续开发提供支持。这些是维护与应用积累的依据，不是稳定性保证。
- [Vue 官方集成指南](https://konvajs.org/docs/vue/index.html)支持 Vue 3，框架生态还包含 React、Svelte 与 Angular 入口。LayerLens 可以继续使用已有 TypeScript 适配器；选用 Konva 不自动意味着引入 `vue-konva`，是否需要声明式包装在正式接入设计中决定。
- [性能指南](https://konvajs.org/docs/performance/All_Performance_Tips.html)与[内存管理说明](https://konvajs.org/docs/performance/Avoid_Memory_Leaks.html)覆盖视口、Layer 数量、事件监听、缓存和销毁。项目应据此设计资源生命周期，但仍以开发测试 MCP 的真实测量验收。
- [Leafer 官方指南](https://www.leaferjs.com/ui/guide/)也提供中文文档、图形编辑器与布局等能力，并将 `leafer-vue` 标为社区组件集成。选择 Konva 是本项目对生态覆盖和维护成本的权衡，不把 Leafer 描述为缺少生态或不成熟到不可用。

后续边界：

1. Rust 继续负责 PSD 解析、规范化模型、文档／选区／任务和资源预算；Konva 只负责前端绘制与交互展示，不引入前端 PSD 解析或另一份权威状态。
2. 正式接入以仓库已锁定的 `konva 10.9.0` 为起点，升级依赖另行评审。选型后移除 Leafer／CanvasKit 实现及依赖，原实验源码和证据保存在本机备份，当前工作树仅保留 Konva 验证入口。
3. 先定义 Konva 工作区接入与现有合成预览的衔接，再分批接入选择／视图和受支持的图层重绘。文字、形状、位图回退与不支持项分别标记；不将源图层诊断投影作为完整 PSD 合成。自动／Ctrl 检查选择保持与任务范围授权分离，PSD 始终只读。
4. 接入前补齐测试 MCP 的逐轮 DPR／视口／焦点观测及终态环境快照，按固定条件验证资源释放、真实交互与保真子集；缺少能力先补 MCP。后续测试围绕 Konva 的产品验收，不再重复相同输入下的三引擎选型矩阵。

## 真实大稿补测边界

私有 `tab-1.psd` 只在本机忽略目录使用。选型实验曾运行两引擎独立进程，当前保留 Konva 独立进程回归；固定源指纹、字体和内容，分别记录严格场景完整性与源图层诊断投影。大稿解析和已有合成预览不等于逐层合成正确。

- `largeRender` 必须与显式 `renderLab` 配置共同启用。单文件源上限 512 MiB、累计声明像素 128 Mi、最多两个存活修订；全局源 1 GiB、声明像素 256 Mi，单次解码仍为 128 MiB。生产默认不变。
- `large`／`largeLayers` 场景最多 2048 层、32 Mi 画布像素、96 Mi 累计几何像素；元数据最多 2 MiB。PNG 从同一修订按需二进制读取，单并发、单项 32 MiB、前端累计 128 MiB；alpha 缓存独立计量，上限 96 MiB。失效发布拒绝，取消后丢弃晚到资源。
- `large` 继续严格能力检查；`largeLayers` 是显式诊断，读取基础文字／路径或已保存图层通道，未实现的画板、组效果、蒙版、剪贴、调整与 ICC 不能视为已合成。每层保留组合成限制；文字映射失败时仅在该模式允许源像素回退，并单独列出图层 ID。
- 测试 MCP 观测场景档位、实际绘制／位图／文字像素回退／降级／缺失 ID、编码及 alpha 字节；通过真实按钮切换档位、适应窗口、定位检查图层，并复用真实平移、倍率、自动／Ctrl 选择、等待和截图。
- 大截图使用 `dev_ui_capture` 固定一次真实捕获，再以 256×256 物理像素 PNG 分块返回；单块仍不超过 512 KiB，客户端验证完整 RGBA 指纹后无损拼接。输入 PNG 最多 8 MiB、解码 RGBA 最多 64 MiB，每实例保留一个快照，60 秒失效；显式释放、替换与退出回收。不得用多次不同时间的截图拼接冒充同一帧。
- 独立参考从原 PSD 保存时合成图提取，关闭 ICC；字体按原 PostScript 名称绑定固定官方文件与哈希。制作时字体版本未知须记录，不能把名称相同解释为字形版本一致。
- 大稿固定资源回归使用三个独立 Konva 进程、每次 20 轮加载／关闭，期间约每秒取样，最后自然空闲 0／10／30／60 秒观察回收。保持采样私有提交峰值 ≤3 GiB、后五轮较第 6–10 轮释放态中位数增长 ≤64 MiB、后 15 轮斜率 ≤2 MiB／轮。峰值额度针对大稿，不修改原小位图门槛，也不构成进程硬限或无泄漏证明。
- OS 采样先枚举候选，再用独立枚举核对创建时间和父子关系，确认归属后读取内存。已确认退出或早于当前父进程的候选以 `observations` 保留；零创建时间不能解释为旧进程，身份未知仍失败。失败采样也保留完整数据，`valid=false`、总量为 `null`；中止的循环不能与完整循环一起排名或记为内存超标。
- 整页视觉、源图层诊断流程和性能门槛分别报告。`completedWithLimitations` 仅表示诊断套件执行完成；存在共同降级时 `fullSceneAccepted=false`。保留全部失败，不据子集速度确定正式渲染器。
- 截图和同步计时须等待资源加载和实际绘制完成，旧缓存放大帧不能当作最终画质或低耗时优势。Leafer 缩放 pattern 队列修复作为历史实现随备份保留，当前不再运行该引擎。

PSD 始终只读。实验不提供文字编辑、图层移动、变换原稿或保存回写。Rust 继续持有文档、选择和任务的权威状态；视图可以保存缩放、平移、悬停、候选及临时按键。现有工作区和工具语义保持原有设计，实验选择交互不自动修改产品约定。

### 真实大稿固定实验结果与限制（2026-10-16）

- 新的大稿资源和分块截图路径已通过真实测试 MCP。就绪修复后的视觉／交互双方各三个独立进程完成，60 张诊断截图与 30 个成对视图核验完成。共同绘制 267 位图，其中 89 个文字源像素回退，原生文字 0；严格场景无可绘制内容，完整 PSD 保真未通过。
- 就绪等待需包含 Leafer 缩放 pattern 队列；修复前的低分辨率缓存截图不能代表最终画质。修复后所取三处 400% 局部跨引擎像素相同，fit 重采样差异仍在；这些是位图投影结果，不能用于原生文字排版排名。
- 同一新采样器版本的六个固定内存实例全部执行，五个完整测量中一个通过、四个未通过固定增长门槛；另一个 Leafer 实例在 17 个完整循环后绘制就绪超时。六实例无残留，919 次 OS 采样有效。完整测量均未超过 3 GiB 采样峰值门槛，空闲后明显回收，不据短循环单独断言泄漏。
- 内存矩阵发生 DPR 1.5 → 1 和失焦；脚本缺少逐轮环境约束及成功终态环境快照。因此同条件三进程公平性验收未通过，不能混合不同 DPR 或不完整实例得出框架排名。若继续实验，先补 MCP 环境观测／断言及就绪阶段诊断，保持失败报告和原门槛，不以自动重试筛选通过。
- 各实例读数、失败成因边界、程序指纹与本机产物见 RENDER-02 归档。该轮结束时渲染器未定；此次实测不支持“Leafer 全面优于 Konva”，也不足以证明相反结论。真实文字与画板／蒙版／组合成能力仍需独立验证；后续工程选型见当前决定。

## 数据与依赖边界

PSD → 现有 Rust 解析适配器 → 有界、带来源的场景 DTO → Konva 适配器。不得在前端另行解析 PSD，或按图层名称硬编码内容。

- 场景携带源指纹、文档与修订、画布尺寸、PSD 像素坐标、图层顺序、可见性、透明度、图层 ID、类型及能力诊断。文字保留原文、分段和变换；路径保留原始几何与填充规则；图层位图包含透明通道。缺失数据明确标记。
- 区分 `native`（由结构数据重绘）、`rasterFallback`（图层像素回退）、`unsupported` 和 `parserGap`。文字／形状回退不能记为原生重绘通过；不能绘制整个合成图后宣称完成图层重绘。
- 首轮只定义实际需要的最小契约，不预建通用编辑器框架。实验扩展与正式模型保持隔离；必要的解析扩展由 Rust 适配器提供，第三方解析类型不能传至前端。
- 当前 EngineData 度量仍为未验证单位。对可复现的生成样本可以声明受限的实验解释规则，但须同时携带来源和限制；不得推广至任意真实 PSD。
- 各轮使用相同字体字节与指纹、画布范围、有效 DPR、缩放和平移。字体缺失或字符覆盖不足报告失败／降级，不静默替换。
- 固定 npm 精确版本与锁文件；评审许可证、维护入口、WebView 支持和安装／运行成本。字体从本地加载，记录初始化方式和资源释放。正式接入前普通构建不包含验证入口、Konva 包和实验字体；验证构建也不得残留未选引擎或 WASM。

## 隔离窗口

采用独立 Tauri 开发测试进程，复用现有 `dev-mcp` 实例隔离与 WebView profile。显式实验配置只在该进程创建实验页面，使用独立会话、目录和缓存；不向用户日常实例打开页面或发送操作。窗口内部标签可以继续使用已有权限限定的 `main`，其页面、标题和进程身份必须明确区分实验实例。

验证窗口展示原稿参考及 Konva 输出，提供倍率、平移、候选列表和错误详情。每个结果记录引擎、版本、样本身份、渲染阶段和能力限制。

测量按独立进程串行执行，固定采样次数并保留全部失败，不自动重试挑选最快结果。场景尺寸与图层数有硬上限，验证不能放宽正式源文件或解码预算。

## 样本与独立参考

第一份简单 PSD 约 10–20 层，覆盖普通文字、分段文字、多行文字、矩形／圆形／曲线路径、透明位图、重叠、分组和隐藏。按当前解析能力逐项建立覆盖表；缺项先定位于解析、映射或引擎，不混成一个失败分类。

样本分两个证据等级：

1. 可重复生成的公开 PSD：校验源结构、像素、坐标、图层与字节契约，用于 MCP 自动回归。生成器生成的合成图只说明样本构造，不是 Photoshop 独立视觉参考；生成图中没有的文字不得被当成缺陷。
2. 独立制作并导出的 PSD／参考图：记录制作工具、字体版本、导出条件、来源／许可与哈希。用于原稿视觉一致性和最终选型。私有文件只留本地；缺少独立参考时仍能完成工程实验，但最终保真结论标为待验证。

原尺寸参考用于位置、大小、颜色和层叠比对。200%／400% 的文字／路径重绘单独检查；不能把低分辨率参考放大当作高清真值。不同 DPI 的证据以真实环境记录，模拟绘制比例不冒充跨屏实测。

## 交互与状态

- 自动选择开关；Ctrl 按住临时启用，松开／失焦恢复，不更改保存的开关值。
- 点击命中提交已有核心选择入口，收到确认后同步选中边界和图层列表。悬停只高亮，不创建快照或改变任务。重叠候选按同一可解释顺序排列，提供切换入口。
- 命中结果附 `pixel`／`path`／`bounds` 精度；透明像素、隐藏祖先、组和文字边界分别验收。共享几何命中与引擎原生命中分开标记，不把共享实现的结果记为某个引擎独有能力。
- 平移、缩放、选择和取消不修改 PSD。关闭／重开、释放或替换场景后，旧异步绘制、字体加载和观测不得发布为新结果。

## MCP 与证据

功能测试必须使用[开发测试 MCP](08-开发测试MCP.md)。在原有白名单语义交互上增加实验目标、真实前端投影与有界等待；不增加任意脚本执行或直接写组件状态的工具。没有匹配能力时先补工具和契约回归。

- 配置、实例身份、加载场景和业务选择复用既有服务；实验专属 IPC 仅由显式实验实例访问。
- 状态包含场景指纹、方案、绘制代次、阶段、错误、字体就绪、实际 DPR／变换、节点／资源数、候选与选中 ID、CPU 提交耗时等可观测事实。`ready` 必须在字体、图片、引擎绘制完成后发布；rAF 等待不能宣称物理屏幕呈现完成。
- UI 输入使用真实 WebDriver 指针、键盘和滚轮；等待以具体场景／方案／代次为条件，失败保留末态。截图保留捕获前后身份，不能混用上一代画面。
- 报告保留版本、操作、源与资源哈希、截图、限制、失败和退出检查。源文件前后哈希一致；实验退出走正常核心关闭并检查本实例残留。

| 数据覆盖 | 逐图层类型与属性：原生、像素回退、解析缺口和不支持，分别记录                                     |
| 视觉     | 原尺寸几何／文字／透明度／顺序，放大清晰度；差异图定位问题并结合目视，不仅用单一像素分数         |
| 交互     | 自动／Ctrl、重叠、透明命中、平移缩放、失焦和核心选择同步                                         |
| 性能     | 解析与场景传输、首次引擎／字体初始化、场景构建、绘制分别计时；相同输入下多次记录                 |
| 资源     | 生命周期对象计数、取消、卸载和重开；JS 统计、应用账本与进程 RSS 分开，不能由对象归零推导内存归零 |
| 工程     | 适配代码、专用补丁、依赖体积、失败处理、测试和后续扩展成本，不仅比较行数                         |

第一轮出口：隔离入口、三个实际引擎实现、真实 Rust 数据、可复现场景、MCP 功能报告与实现比较。证据不足的能力保持未验证；最终选型还需独立原稿参考及暴露薄弱点的补充样本。结果允许保留原合成预览或采用分阶段方案，不预先锁定胜者。

## 分批实施

### 第三轮收敛结果与当时的主候选（2026-10-16，历史）

当时暂以 **LeaferJS 作为工作区重绘的主候选**，保留 Rust 场景边界、参考图回退和独立渲染适配器；Konva 保留对照，CanvasKit 保留原生段落／路径的专项证据。该倾向随后经用户要求暂停，现已由 2026-10-17 的 Konva 决定取代；本节仅保留第三轮实验依据，不代表当前选型。

第三轮先修复共同数据层：实验像素读取不再套用独立素材导出权限；图层 opacity 只应用一次，普通逐层合成可读取透明位图；支持无羽化／密度／反向的简单灰度蒙版，以及全局 mask kind=128 的逐层值。保留未知属性、其他蒙版组合、多子路径与复杂效果的明确拒绝。正式独立素材导出条件不变。真实 ArialMT 使用本机同一字体字节，源自动行距按明确比例解释；Leafer／Konva 的点文字按实际引擎基线定位。

参考由 psd-tools 1.10.9 独立解码 PSD 保存时合成图，关闭 ICC 转换，不重新合成图层。四样本为 `2layers`、透明图层、三行 Arial 文字和单蒙版。三个引擎分别在 100%／200%／400% 留图，三轮共 12 个实例、36 个原尺寸引擎对照通过；最终程序另做 4/4 确认。最小样本均无未绘制层。普通位图最大通道误差为 1，透明图层和蒙版的 Leafer／Konva 样本误差为 0；真实文字三行的边界相差不超过 1 px，1 px 容差内前景召回最低约 99.78%。截图已目视检查，400% 文字由原生节点重绘。该结论只覆盖这些样本，不扩大到中文复杂排版、任意字体或 Photoshop 全部效果。

像素对照暴露并修正了三引擎采样不一致：Leafer／Konva 初始默认平滑采样，CanvasKit 为 nearest；统一位图 nearest 后通过原阈值，未提高视觉容差。nearest 是本实验的像素检查策略；正式产品缩放时的平滑策略需单独确定。

资源和交互分别使用单引擎独立进程，每引擎三份预定报告，结果如下：

| 项目                                   | LeaferJS            | Konva                       |
| -------------------------------------- | ------------------- | --------------------------- |
| 2000 小位图、20 轮打开／关闭，最终矩阵 | 3/3 通过固定门槛    | 0/3，释放态增长斜率均超门槛 |
| 私有提交量采样峰值（MiB，三实例）      | 814.5／874.3／893.1 | 566.6／585.5／602.2         |
| 后 15 轮释放态斜率（MiB／轮）          | 1.29／−7.38／1.21   | 2.50／5.92／5.56            |
| 960×600 混合长页交互                   | 3/3                 | 3/3                         |
| 同步绘制 P95（ms，三实例范围）         | 3.8–4.1             | 4.2–4.7                     |
| 平移输入至应用就绪 P95（ms）           | 5.5–6.2             | 1.8–2.0                     |

Leafer 占用更多内存；Konva 在该混合长页的平移处理更快，两者均低于预设 50 ms 门槛。结合第二轮密集文字表现、第三轮最小视觉及当时资源矩阵，形成了优先验证 Leafer 的历史倾向，不能解读为所有场景的性能赢家。

资源限制必须保留：早期各有一份有效内存诊断失败，Leafer 峰值约 915.8 MiB、释放态斜率 3.65 MiB／轮；Konva 约 600.4 MiB、6.08 MiB／轮。没有靠强制 GC、删除失败报告或放宽门槛获得通过；后续六个独立试验全部执行，汇总仍因 Konva 失败而标记失败。若将早期诊断与最终矩阵合看，Leafer 为 3/4、Konva 为 0/4。主要增长位于 WebView，应用自身约 27–30 MiB；这些离散短循环结果不能证明泄漏，也不能证明长期稳定。迁移时须保留同一资源回归；若候选持续失败，应先查共享图像／字体与浏览器缓存生命周期，再评估替换引擎。

原交互回归 2/2、业务 2/2、普通发行测试入口关闭 1/1 通过。新的 1280×900 窗口／960×600 视口与资源采样均由开发测试 MCP 完成。完整原始结果、失败历史、软件指纹及产物清单统一维护于 RENDER-01。

### 第二轮实测结果（2026-10-16）

安全内存采样改为可选 `sysinfo` 封装，保持全仓库禁止 `unsafe`。Windows release、WebView2／EdgeDriver 155.0.4283.45、DPR 1.5 下，通过测试 MCP 完成 36 个共享布局实例、6 个原生排版实例、18 个公开真实 PSD 实例和 3 次原交互回归；另验证普通 release 拒绝开发参数。中间的段落样式初始化失败和真实失焦失败单独保留，修复后建立新批次，不覆盖旧报告。完整证据与限制见 [RENDER-01](../devlog/_fin/261016/RENDER-01-渲染器对比实验.md)。

下表为共享布局的同步绘制就绪中位数／P95（ms），合并 100%／200%／400%，每引擎每场景 27 项。视口固定 640×420，全部源节点实例化，部分节点位于视口外；包含公共 Canvas 读回屏障，不是纯 GPU 或物理呈现耗时。

| 场景                | LeaferJS  | Konva      | CanvasKit |
| ------------------- | --------- | ---------- | --------- |
| 2000 路径层         | 4.7／8.5  | 8.0／10.5  | 3.9／7.8  |
| 2000 文字层         | 3.6／6.5  | 14.4／17.4 | 6.4／7.7  |
| 2000 小位图层       | 9.9／16.8 | 9.6／16.2  | 7.9／36.1 |
| 750×8000 长页       | 2.6／4.0  | 3.2／4.6   | 2.2／4.1  |
| 6 张 1024×1024 位图 | 2.5／4.4  | 2.0／4.4   | 2.2／3.3  |

原生模式的 2000 文字层中位数分别为 4.6／16.4／7.1 ms。中文样本中的四个文字层，CanvasKit 全部使用 ParagraphBuilder；Leafer／Konva 当前适配器有三个原生段落和一个共享分段回退。这是当前适配覆盖，不表示其他框架无法通过扩展实现富文本。三种输出的中文、换行和旋转均已查看，仍没有对应 Photoshop 文字真值。

内存不能忽略：2000 小位图场景在各引擎作为进程首用时，整个应用及 WebView 进程树的私有提交量约为 913.9／525.4／678.4 MiB，每引擎只有一个此位置的样本；不能当作稳定分布。后续位置会包含前序引擎缓存，释放显式对象后 OS 内存没有相应归零。当前证据不足以证明没有长期泄漏，需继续核对缓存与长时增长。

真实 PSD 的流程成功与视觉成功分开：六份公开样本中只有 `2layers` 无未绘制层；其余五份存在独立像素读取、缺少 ArialMT、蒙版或未解释属性等缺口。这些首先是共同 Rust 场景的覆盖边界，不能据此断言三个渲染器缺少对应绘制能力。独立 `masks/2.png` 对照中，三引擎、三轮各 3600 个可见像素采样均有约 72.9% 的最大通道差超过 8，符合共同场景缺失的诊断。该诊断未校正浏览器重采样或 ICC，不能单独作为保真评分。

条件性结论：不能继续把 Konva 当作性能默认优胜者；Leafer 值得优先验证长文档与密集文字，但小位图内存成本需要解决。Konva 保留作工程／内存对照，CanvasKit 保留原生段落与路径对照。正式选型仍未通过视觉门槛，下一步先补最小真实 PSD 的像素读取、字体绑定和蒙版场景语义，再复测受影响样本。正式工作区暂不迁移。

### 第二轮选型补测范围（已执行）

2026-10-16 确认并执行下列隔离补测。视觉准确性与交互正确性为通过条件；通过后比较开发维护成本与性能。补测前曾暂以 Konva 为工程默认候选，第二轮数据已将后续验证优先级调整为上文的条件性结论，尚未作出正式迁移决定。

- 真实样本使用有来源／哈希的公开 PSD、固定字体与独立参考；缺字体、未支持蒙版等按层报告，不能作为成功的完整重绘。生成样本与独立参考分开统计。
- 在显式实验配置内增加受限规模读取，目标覆盖 100／500／2000 层、文字／路径／位图和长页面；不改变普通文档预算。所有传输、像素、图层和观测条数仍有硬上限。
- 保留共享布局基线，增加原生文字模式。CanvasKit 使用 ParagraphBuilder；其他引擎按实际支持表达，富文本缺口明确报告。源文本框来自 PSD EngineData，不能由图层像素边界猜测。
- 首次引擎在空实验窗口中预选，冷运行使用新进程／WebView profile；热运行在同页重复，三种顺序循环轮换。相同样本、字体、DPR、视口和绘制就绪屏障；截图编码在测量区间之外，连续输入不生成 PNG。
- MCP 扩展只读性能观测与本实例进程资源采样；报告保留原始采样、失败与中位数／P95。浏览器调度、Canvas 读回与 OS 内存各自注明口径，不能代替物理屏幕呈现、GPU 显存或无泄漏证明。
- 补测结束形成能力矩阵和条件性选择；如果真实原稿视觉证据仍不足，保留明确待办，不以工程回归通过推导最终保真。

1. 落地设计／计划；核对解析数据，建立样本、受限场景 DTO 与开发隔离入口。
2. 实现三个适配器及统一视图参数，接入本地固定字体、资源释放和错误投影。
3. 补齐 MCP 操作／等待／截图，执行选择与变换、重复切换／关闭、普通构建隔离回归并保留报告。
4. 对独立参考、真实 DPI、代表性样本补证据，形成选型结论；用户确认后才单独规划正式工作区迁移。
