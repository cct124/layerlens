# PSD 首版支持与解析器决策

## 决策与依据

2026-09-17，M0 将 `ag-psd 0.3.0 + LayerLens patch 3` 固定为首版支持子集的解析实现，继续通过 Rust 核心适配器隔离。版本、源码来源和局部修改见[补丁记录](../vendor/ag-psd/LAYERLENS-PATCHES.md)，逐样本结果、独立参考及性能证据见[M0-01 结果](../devlog/_fin/260917/M0-01-PSD解析验证.md)。

选择依据是已有结构、文字原始数据、保存时合成图及简单位图路径达到有限范围的验证要求，已发现的容器兼容缺口可以用局部补丁和独立回归约束。本次没有增加运行时依赖或引入第二套解析器，也没有完成其他候选的同条件性能比较。此决策用于进入 M1；桌面集成、进程总资源管理和发布验收仍须单独完成。

## 首版可声明的范围

以下是解析与数据提供范围；不代表同格式的所有 PSD 都可打开。调用方必须读取文档、图层及属性的实际能力和诊断，不根据扩展名或成功打开推断完整支持。数据语义统一遵循[PSD 数据与素材](03-PSD数据与素材.md)。

| 能力          | 可提供的数据或行为                                                                 | 限制与证据边界                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| 输入容器      | PSD v1、RGB／8 位、3／4 个合成通道、RAW／RLE；按边界验证后读取                     | PSB、ZIP、高位深和其他颜色模式拒绝；已知图案通道缺口仍可能使 RGB8 文件失败                                                           |
| 文档与图层    | 画布、文档像素边界、层级、可见性、类型、原始记录索引与来源诊断                     | 组、文字、位图、形状、智能对象、调整层和未知类型的分类不等于具备对应渲染能力                                                         |
| 文字事实      | TySh 原文、UTF-16 区间、原始矩阵；校验后的字符／段落分段、显式字体引用、属性及来源 | 样式仍为 `partial`；EngineData 度量为 `unverifiedEngine`，字体可用性、字重、物理单位和完整排版未验证；不生成 CSS                     |
| 合成预览      | 按需解码 PSD 保存时合成图，保留已验证的 global alpha 语义                          | 不重绘图层，不验证合成图是否反映当前图层内容；合成图可以是占位内容。ICC 只记录存在性、大小和指纹，有 ICC 时预览为 `partial`          |
| 独立 PNG 素材 | 通过能力检查的普通位图完整通道，保留透明边缘和画布外部分                           | 图层和祖先必须有效可见，且没有未验证的蒙版、效果、剪贴、混合或其他视觉依赖；组、文字、形状、智能对象等独立导出未开放；未执行色彩转换 |
| 降级与失败    | 未知区段在完整边界校验后跳读并附诊断；明确未实现的能力可分项降级                   | 结构损坏、截断、越界和预算错误保留失败；不以放宽 strict 或无条件跳过错误扩大支持范围                                                 |

工具提供带单位、坐标、变换、来源与限制的设计事实，由 Agent 根据目标项目决定 CSS、布局、响应式方案和字体替代。原始度量尚未确认不阻断其他已验证数据；后续若能验证单位，增加明确语义与证据，而不将项目相关的 CSS 转换变为解析器职责。

## 已确认限制

- 公开 EXE `01_home_light.psd` 在放宽实验像素预算后仍因 `Patt` 中的 RAW 图案通道触发候选 `Invalid color pattern`，正式入口返回 `ParseFailed`。这是已定位的兼容缺口；解决前不能声明支持该文件。后续须先独立验证通道结构和语义，再决定实现或带诊断跳读，保留损坏数据回归。
- 保存时合成图的读取不能证明图层重新合成正确。`masks/2.psd` 内保存的是全白 RGB；上游配套 PNG 检查的是重新合成后的蒙版 alpha，两者不等价。独立参考只证明已比较的像素，不推广为蒙版、Knockout 或效果渲染支持。
- 当前公开页面的独立素材大多受全局蒙版、祖先或自身视觉依赖阻断。成功预览不代表整页可拆成独立素材；复杂导出保留到 M3 按逐特性参考验收。
- Photoshop 字体度量／排版、ICC 全流程及复杂效果缺少完整独立参考；合成样本只能验证编码约定与公开行为，不能代替这些验收。

## 资源与后续实施

核心默认保持源文件 64 MiB、累计声明像素 16,777,216、4096 条图层记录、64 层组嵌套、单次解码 128 MiB。累计像素包括画布、图层及蒙版，不能用压缩文件大小或画布面积替代；这些是准入及单次解码保护，不是进程总内存硬上限。

公开批次中，默认配置下 15／21 份完成读取与预览；显式实验配置下 17／21 份完成，3 份高位深被拒绝，1 份受上述图案问题阻断。长页和中等页面分别用 134,217,728、33,554,432 累计像素预算完成正式测量；这些配置仅对应样本实测，不修改默认值，也不构成通用性能承诺。

后续集成按 Rust 核心文档注册、打开／关闭／切换、有界后台执行及结果发布规则，再到有预算的预览缓存和薄 Tauri 接口的顺序实施。必须验证取消后不发布过期结果、关闭释放、多文档总资源限制和界面响应；同步 CLI 的打开、PNG 和释放数据作为比较起点。实际实施与验收结果见[M1-01 记录](../devlog/_fin/260920/M1-01-文档生命周期与后台任务.md)，当前优先顺序以[开发记录](../devlog/README.md)为准。

保留现有适配器和最小局部补丁；后续每项扩展先补独立样本与预期，再调整能力声明。若目标能力需要大面积维护候选内部实现，或无法满足内存与取消要求，再用同一语料评估补充实现或替换，不默认同时维护多套生产解析器。
