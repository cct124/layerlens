# 实施与验收

## 当前状态与实施原则

当前仓库仅有项目说明、协作规范与本套设计文档，以下阶段均为规划。首轮工程任务从验证 PSD 解析与导出能力开始，不将候选解析器的说明直接当作首版验收结果。

先验证真实设计数据，再建立共享核心与交互，最后完成 Agent 闭环。每个阶段以可复现结果作为出口；进度、失败尝试及下一步记录在 `devlog/`，不在多份设计文档中重复维护任务状态。

## 阶段与出口

| 阶段             | 主要工作                                                                       | 完成条件                                                                                |
| ---------------- | ------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------- |
| M0：解析原型     | 评估 Rust PSD 候选库，整理真实和合成样本，提取文字、边界、预览及简单位图       | 输出样本能力矩阵、准确性差异、耗时与内存基线；确定首版支持子集及解析器版本              |
| M1：工程与查看器 | 建立 Rust + Tauri 工程，确认界面框架，完成打开文档、合成预览、图层树和属性面板 | 一份真实活动稿可打开、定位图层和查看样式；加载失败保留旧文档，长操作可取消              |
| M2：选择与快照   | 实现图层多选、区域选择、版本化摘要、不可变快照与任务生命周期                   | 选区与画布坐标一致；任务不受切换、清空、重载和响应乱序干扰                              |
| M3：预览与素材   | 裁剪参考图、按需解码、受支持 PNG 导出、清单及错误处理                          | 参考图与独立素材语义正确；成功文件可用，失败效果可识别，无目录越界和意外覆盖            |
| M4：MCP 闭环     | 内嵌服务、工具 Schema、结构化响应、图像、分页与 Agent 使用规则                 | 本地 Codex 可固定一个选区，读取样式和图像、使用导出素材，完成一个真实 H5 模块并对照验收 |
| M5：扩展验证     | 文字片段、模块持久化、资源通知、stdio 桥接、Codex 会话控制及更多格式           | 按独立需求和样本逐项验收；不作为首版发布前置条件                                        |

MCP 联通原型可在 M1–M3 期间提前验证，避免到 M4 才发现传输或客户端兼容问题。不得因提前联通而跳过快照和导出验收。

## 样本集

| 样本               | 验证内容                                                         |
| ------------------ | ---------------------------------------------------------------- |
| 最小 RGB／8 位 PSD | 画布尺寸、分辨率、基础图层顺序、合成图与透明 PNG                 |
| 真实 H5 活动稿     | 长页面、嵌套分组、常用文字和按钮、实际素材组合                   |
| 多样式文字         | 字体、字号、颜色、字距、行距、对齐及同一图层内的样式分段         |
| 特殊字符文字       | 中文、换行、emoji、组合字符，UTF-16 区间与原始文本一致           |
| 变换与尺度         | 不同 DPI、文字缩放、旋转、非均匀变换、小数及负坐标               |
| 层级与视觉依赖     | 重名图层、隐藏父组、透明边缘、蒙版、剪贴、阴影和父组效果         |
| 异常输入           | 无合成图、损坏文件、截断数据、超预算尺寸、首版不支持的模式和位深 |
| 规模样本           | 不同文件大小、图层数、画布尺寸与可解码像素量，用于性能及缓存验证 |

样本附预期图层信息和参考截图或已核对的属性值。项目外的真实设计稿不直接提交公共仓库；可公开样本记录来源和许可，私有样本通过可复现说明参与本地验证。

## 核心验收场景

| 场景                                 | 预期结果                                                                  |
| ------------------------------------ | ------------------------------------------------------------------------- |
| 打开新文件失败，或旧加载请求晚完成   | 不覆盖最新有效文档，失败与取消状态明确                                    |
| 在多个缩放比例下点击和框选           | 选择范围保持相同文档坐标；不重复应用 DPI 或视图缩放                       |
| 选中组及其子图层、或选择重名图层     | ID 定位准确、目标去重，不重复导出                                         |
| 框选只经过某组的局部                 | 保留区域与相交候选，不自动扩大到整组                                      |
| 读取文字和分段样式                   | 对应原稿属性；缺失字段、推导值和复杂变换均可识别                          |
| 绑定 A 后选择 B、清空或切换文档      | A 的业务结果不变，摘要准确反映当前选择与新版本                            |
| 源文件被覆盖后继续读取旧任务         | 使用旧修订固定的数据，或明确报告不可用；不混入新文件像素                  |
| 响应乱序、重复创建任务、释放任务     | 旧选择不覆盖新状态；创建幂等；释放不再接受新的读取                        |
| 未绑定快照被回收或应用重启           | 明确返回生命周期错误，不自动绑定其他范围                                  |
| Agent 高亮及多连接操作               | 不改变用户选择；各连接高亮互不覆盖，断连后清理                            |
| 导出不支持效果或部分图层失败         | 默认拒绝不受支持的导出，逐项报告，成功清单只引用完整文件                  |
| 图层名包含路径字符，或导出位置已存在 | 输出仍在配置目录内，名称安全且唯一，不覆盖已有结果                        |
| MCP 分页、图像和错误响应             | Schema 有效、范围一致、图像可被客户端读取、错误可定位和恢复               |
| H5 模块实现                          | 在明确 CSS 比例和字体条件下核对字号、颜色、布局及素材；范围始终受用户控制 |

## 性能与诊断

先建立样本和环境基线，再设定性能预算。不得在尚未实测时宣称“大文件秒开”或比其他语言方案更快。

每次性能实验至少记录操作系统、CPU、内存、构建模式、依赖版本、样本指纹、文件大小、图层数、画布尺寸及冷／热缓存条件，并区分：

- 打开文件到元数据可用、到首张预览可见的耗时。
- 选择与属性展示的响应耗时，后台工作期间的界面可操作性。
- 解析、解码、裁剪和导出的阶段耗时及峰值内存。
- 缓存命中、回收效果、连续切换文档后的占用。
- MCP 响应延迟、JSON／图像大小、分页和取消行为。

M0 依据样本结果提出资源上限、并发数与响应预算，后续阶段验证而非凭经验写死。用户可感知的卡顿须单独验证，不能仅用后台吞吐量替代。

## 检查与交付

- 文档变更检查链接、示例及跨文档一致性。
- 工程建立后，在项目 README 中列出实际格式检查、类型检查、lint、测试、构建和启动命令；当前不虚构可运行脚本。
- 测试优先覆盖样式规范化、字符索引、快照并发、范围校验、导出边界和失败处理，不为简单实现细节重复编写测试。
- 验证报告区分静态检查、运行测试、图像对照及性能实测；视觉近似不能表述为 PSD 完整兼容。
- 工程阶段完成或交接前更新任务记录，保留环境、结果、限制和下一步入口；纯文档工作无需建立 `devlog/`。
